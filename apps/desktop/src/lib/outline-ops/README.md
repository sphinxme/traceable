# 结构操作层（outline-ops/）

结构操作层是**全应用唯一允许修改大纲拓扑的地方**（G2）。任何创建、改边、删边、级联删除都必须经过这里；组件与适配器不得直接写 `children` / `parents`。

## 为什么需要这一层

一次“缩进”或“拖拽”并不是单一写操作：它要改一条边、迁移折叠子树、展开落点父，还要在失败时保证数据、折叠与 UI 都不留残余。把这些规则集中在 Ops 后：

- 环、重复边、存在性只在**一份实现**里判断；
- 数据与折叠在**同一个 Yjs 事务**内完成；
- 下游拿到的不是“意图”，而是事务后的 **post-state 描述符**；
- 可预期失败以返回值报告，统一 abort，不产生副作用。

## 8 个操作

| op        | 一句话语义                     | 折叠动作                         |
| --------- | ------------------------------ | -------------------------------- |
| `insert`  | 新建实体并挂到父列表指定槽位   | 展开落点父                       |
| `split`   | 在光标处截断标题，前缀归新任务 | 展开落点父                       |
| `indent`  | T 成为前序兄弟的末子           | 迁移 + 展开新父                  |
| `outdent` | T 成为父的后一兄弟             | 迁移 + 展开新父                  |
| `move`    | 同父 reorder / 异父 reparent   | reorder 无；reparent 迁移 + 展开 |
| `link`    | 新增一条边，源出现保留         | 不迁移；展开落点父               |
| `unlink`  | 删一条边；末边转 remove 级联   | 删除 from 折叠子树               |
| `remove`  | 删边；末边则“无边即亡”级联     | 删除折叠子树 + 全 panel prune    |

另导出 `newTaskId()`（纯 id 预生成）与 `checkDrop()`（拖放预检谓词）。

## 统一骨架

```
① 结构校验          ref / cursor / id 占用 → invalid
② 执行时重校验      存在性 / 环 / 重复 → notFound / cycle / duplicate
③ 同一事务          数据原语 → 折叠原语
④ post-state 描述符 事务后回读实际位次与结果
```

② 与 ③ 之间没有异步间隙：重校验针对的是“意图快照组装”与“真正执行”之间的窗口。

## 边语义与多父

`indent / outdent / move / unlink / remove` 的作用对象是 `EdgeRef`（一条父→子边），不是实体：

- 改一条边，同一实体的其他出现保持不动；
- 删除一条边后，若实体仍有其他父边则存活；
- 只有最后一条边消失时才触发“无边即亡”的级联删除；
- 折叠迁移只发生在 `view` 指定的出现上，其他出现的折叠态不受影响。

## 失败语义

- 可预期失败一律返回 `{ ok: false, reason }`，不抛出；
- 失败路径不改数据、不迁移折叠、不产生目标命名、不发焦点；
- `perform` 对 op 抛异常做最后兜底，视同 `invalid`；
- 成功但并发修改了落点时，描述符报告**实际** post-state，消费者不假设意图精确达成。

错误面：`cycle` / `duplicate` / `notFound` / `invalid`；越界 `toIndex` 收敛，不视为失败。

## 预检与权威校验同源

适配层在 dragover 调 `checkDrop()` 做光标反馈，执行期 Ops 再做一次权威校验。两者共用 `check.ts` 的同一份谓词，禁止各写一套。

## 边界

- 不碰 DOM、光标、动画、焦点；
- 不做 UX 决策（提示归适配层）；
- 不做导航（导航路径写入归 `EditorPanel`）；
- 不感知 Registry / ViewHandle / settle。

每个 op 的精确事务步骤、前置条件、折叠动作与描述符字段见 `ops.ts` 的方法 JSDoc；谓词语义见 `check.ts`。
